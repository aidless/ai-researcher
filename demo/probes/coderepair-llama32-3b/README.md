# 探针：`llama3.2:3b` 在 coderepair 同一批 40 题上的两策略读数

## 这是什么 / 这不是什么

**是**：一发补测。`demo/runs/coderepair-01` 里 `llama3.2:3b` 那两个格是 40/40 条
`HTTPError 404`（模型没装，`run_coderepair.py:56-75` 的 preflight 后来把这条堵住了），
所以那一臂一直只有 3 个模型有数据。本机 `ollama pull llama3.2:3b` 装好之后（现读
`ollama list` 有它），用**同一个默认 seed、同一批 40 题**把这个模型补上。

**不是**：一支注册过的 run。这里没有 `envelope.json`、没有 bundle、没有签名、没进
`line_registry.jsonl`，也没走 `loop.cmd_run` 的 kill-switch/评审两席 ⇒
**任何论文主张不许引用本目录当证据**，它只支撑一句"这个模型的这一格现在有数了、方向是正的"。
另注：`run.log`（起止时间戳与 rc）**没有入库**——本仓 `.gitignore:136` 排除 `*.log`，
我不为一份探针日志破例。所以下文那句"本机实测 54 秒"是本轮实测、**其载体不在版本库里**，
要引用时长就得自己重跑一遍拿回执，别把它当可复核的数。
要转正就得开一发正式 run（成本 ≈ 80 次调用，本机实测 54 秒，见 `run.log` 的首末时间戳）。

## 怎么跑的（整条取自载体，可原样重放）

```bash
cd ai-researcher
EVO_MODELS=llama3.2:3b EVO_OUT=/tmp/probe_llama32/artifacts \
  python3 demo/coderepair/run_coderepair.py
# 16:31:22 → 16:32:16 本机 CST，rc=0
```

`EVO_OUT` 指到仓外临时目录，产物再拷进本目录——刻意如此：环境变量泄漏是这仓犯过的错
（一个测试的 `EVO_OUT` 漏进下一个测试），把写出点钉在显式路径上并留下 `run.log` 才对得上。

`demo/runs/coderepair-01/round-01/artifacts/items.json` 的 40 个 `id` **集合相同且顺序相同**
（现算 `set(a)==set(b) and a==b` → True）⇒ 与 01 池里那 3 个模型同题同序，可以并排比。

## 与那三个模型并排（同 01 池，配对数由 `result.json.models[*].detail` 逐题重算）

| 模型 | direct → step-calc | delta | fixed/broke | p | 判读 |
|---|---|---|---|---|---|
| qwen2.5:7b | 0.525 → 0.550 | +0.025 | 8/7 | 1.00 | 无可探测效应 |
| qwen2.5-coder:7b | 0.525 → 0.525 | 0.000 | 4/4 | 1.00 | 无可探测效应 |
| gemma3:4b | 0.625 → 0.375 | **−0.250** | 0/10 | 0.0020 | **resolved 有害** |
| llama3.2:3b（本探针） | 0.425 → 0.575 | **+0.150** | 11/5 | 0.2101 | 正向但未 resolved |

四模型均值 = (0.025 + 0 − 0.25 + 0.15)/4 = **−0.0188**（原来三个模型是 −0.0750）。

## 这条读数改变什么、不改变什么

**改变的**：这一臂的真实形状不是"step-calc 有用/没用"，而是**符号随模型容量翻**——
两个 7B 是平的，4B 显著受损，3B 正向（还没测开）。定价板那句"要买的是『哪个模型上成立』那一层"
现在有了第四个点支持，而不是只有推测。

**不改变的**：`NOT_FUNDED`（撤回 40→157 那发）的结论照旧。
把题数加到一个**均值仍为负、且四模型符号相反**的合并主张上，加样本不会把它翻正；
真要买的东西换名字了——是"按模型分层的主张 + 每个模型各自够的功效"，不是同一个池的题数。
3b 这一格要从 p=0.21 走到能判，按 `n=(2.802×sd/目标)²` 需要的不是 157 题这个池，
而是这个模型自己的更多题/更多 rep（本轮没算它的 n，因为单模型 sd 无载体）。

## 没做的

- 没在 02 池（48 题）上补 3b ⇒ "跨池复制"目前只对 gemma3 成立。
- 没做 rep/种子重复 ⇒ 单点读数，方差未知。
- `llama3.2:3b` 的 404 当时为什么发生（模型没装却被请求、异常被吞成 0.0）已由 preflight 堵住，
  但**旧产物里的 0.0 没有被追溯改写**，只在读数侧排除——这是刻意的，改历史产物比标注更坏。
