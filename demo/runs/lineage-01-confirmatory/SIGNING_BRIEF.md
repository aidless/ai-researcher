# 签署简报（60 秒版）

> 目的：让你在最短时间内做出**知情**的签署决定。全文只三个问题。
> 执行器已就绪并通过测试：未签拒跑（exit 4）、sha 漂移拒跑（exit 4）、
> 竞争进程拒跑（exit 3）、锁被活进程持有拒跑。**签名前不可能流出任何数据。**

## 你要签的到底是什么（三件事）

**1. 主 estimand：端到端任务成功率差（v3c − v3b）**
- 非答案计 0（而不是 0.5、不是删掉）——这一条死后不许改
- 敏感性（0.5 / 1.0）只作次要呈现，不参与判决
- paired Wilcoxon + 符号检验 + bootstrap CI + rank-biserial + HL，一套到底

**2. 三个次要 estimand**（不校正、只报告）
- 条件答案质量（仅两臂都有分的题）
- 可用性差（不终止率）
- 法官不对称（frozen 旧规则 vs 现行规则的删除率）

**3. Kill switch 五分支**（最关键的是前两个）

| 条件 | 动作 |
|---|---|
| 端到端 Wilcoxon p≤0.05 且 **v3c 更低** | 主结论成立（端到端退化可复现）→ 进人工标注复核 |
| 端到端 **不显著** | STOP-REFUTED：pilot 的端到端信号不复现；条件轴与法官 bug 结论**不受影响**（它们不依赖本轮） |
| 新题上 old 删短答、new 不删 | 机制 CONFIRMED（与端到端判决**独立**） |
| 新题上 old 也不删 | 机制收窄为题项特异 → 回退 case-study 定位 |
| 任一臂非终止率 >20% | 先查 infra（独占记录），排除后再谈模型 |

**注意第二节**：不显著是**预设的合法结局**，不是失败。签了名就要接受
"可能花了 4 小时得到一个阴性"，这就是预注册的意义。

## 你不必现场做的

- 读 150 题：题库已机器验证（格式零失败、sha256 `ec6a7242…`）；
  执行器另有人审项在 PREREG §7b，但那是**签名后、收数前**由执行人逐项打勾，
  不是你的签字成本。建议你**抽查 5 题**（随机抽 `d` 开头即可）。
- 理解统计细节：上面三个 estimand 就是全部；run 由执行人做。

## 签哪三个空

`PREREG.md` §8，抄这三行（把方括号换掉）：

```
- `approved_by`：[你的名字或 ID]
- `approved_at`：[YYYY-MM-DDThh:mm:ss，现在的时间]
- `bank_sha256`：ec6a72426aa08d671ff8c518e6ac8a9a26ad733a5525282f7be3291cca32aff4
```

第三行是**题库指纹**：执行器会重算核对，题库若被动过立刻拒跑。
你不需要手抄这行——签完名字和日期，执行器会告诉你填什么。

## 签完之后发生什么

1. 执行人（agent）跑 §7b 三检查：题库人审抽查、构件可加载、机器独占确认
2. 找你闲的机器窗口（这台 GPU 现在 71%，要等）
3. `python3 confirmatory_run.py v3b 0 25` 逐块推进（每块约 20 分钟，共 12 块）
4. 全部 150×2 做完后自动 scorer，出 `result.json`
5. 按上表判 kill switch，出 verdict —— 然后才轮到论文动笔

## 我不代签的理由（一句话）

`approved_by` 写你的名字，未来审稿人问"这是你批准的吗"，你答得硬气；
写我的或者写"agent 代签"，这一轮的全部价值就没了——它的存在就是为了
解决 post-hoc，而口头批准不能比手签更严（我说过“空着就是没签”，现在自己
改口径就是移动门柱）。
